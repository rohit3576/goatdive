THE --SCRIPT ENGINE SAGA (for the completion doc — hard-won this session)
--------------------------------------------------------------------------
New findings on top of Phase 8's divergence lesson:
- PHYSICS-SIDE AND IDLE-SIDE STATE FORK IN PRACTICE: idle-written
  Input.action_press is INVISIBLE to physics-side Input.is_action_
  pressed reads (intermittently — timing of the write vs burst windows);
  idle-written rotation.y invisible to physics sibling callbacks; idle
  reads of physics-written transforms show stale values. SCRIPT VAR
  reads/writes (set()/get()/metas) DO cross reliably. Signals cross
  reliably.
- LATE-ADDED NODES' ENGINE CALLBACKS NEVER FIRE under --script: a
  file-backed helper script added mid-run had ticks=0; added at mount →
  ticks fine. Mount test scaffolding EARLY.
- SOURCE-COMPILED SCRIPTS (GDScript.new() + source_code) register
  direct calls fine but NOT engine callbacks; file-backed scripts
  register callbacks (the gauntlet-brain pattern).
- WORKING PATTERN for physics-timed injection: a file-backed helper
  node mounted at start, armed via meta flags, acting per physics tick
  (smoke_spin_writer.gd does spin-rate + arm_flip→detector._begin_flip).
- Wall-clock waits give ARBITRARY physics progress; settles must be
  OBSERVATION-GATED (poll calm: grounded && !tumbling && !stumble).
- macOS has no `timeout` command — background + sleep + kill + read
  the redirected log instead.
- Whole-battery run time: 2-6 min depending on poll timeouts; run
  DETACHED (nohup … > /tmp/x.log &) and poll the log, never block.
